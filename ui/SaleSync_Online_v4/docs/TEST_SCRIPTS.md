# Acceptance checklist

1. Open the all-in-one HTML and sign into each of the four accounts in TEST_ACCOUNTS.txt. Check wrong-portal rejection, registration, sign-out and password visibility.
2. Inspect Home at phone and desktop widths. Category icons should be clear, the carousel should use manual dots, and no pause control should appear.
3. Choose Accessories, then Jewelry in the left sidebar. The sidebar should narrow Accessories rather than repeat marketplace categories.
4. Open a photographed apparel product, switch sizes/options and views, and add the selected option to the cart. Check Seller Products → Options for color/design/price/photo editing.
5. Compare two mice. Verify a meaningful table, selected options and no Compare Now launch tray. Select unlike product types and verify the grouping prompt.
6. Open Messages as Customer and Seller. Search conversations, send a message, filter unread and review related orders. Confirm other users' threads cannot be opened.
7. Add Home and Office addresses. Choose Office at checkout; the stored default must remain unchanged. The invoice/order must retain the selected label and recipient snapshot.
8. Select one delivered shop and one pickup shop. Apply shop, platform and shipping vouchers. Check minimum-spend/expiry/usage explanations and that pickup never receives shipping credit.
9. Complete a paid TechHive order. Use Seller Orders to pack and mark ready. For pickup, find the code in Customer tracking and verify Seller collection; reject a wrong code.
10. Open the invoice. Check line items/options, unit prices, recipient, shop names, discounts, shipping and total. Print/save PDF or download HTML.
11. Request a return for a delivered purchased option with evidence. Seller accepts, Customer records dispatch/tracking, Seller inspects, and Management authorizes the capped refund. Confirm restock occurs once.
12. Test refund-only, rejected request/appeal, duplicate quantities and duplicate refund rejection. Open returns should hold automatic completion and payout eligibility.
13. Management must view the seller application and confirm review before approval. Test Needs Information and reasoned rejection.
14. Suspend an account using a category, duration and reason. Inspect the audit before/after values and timed restoration.
15. Request a seller explanation on a product. It stays visible until a response/deadline and final recorded decision. Seller responds from Products; Management reviews the reply.
16. Review Order Oversight and Payment Status. Compare payment/order totals and inspect attempts/refund events. Management should not manually mark production payments paid.
17. Filter Sales Reports by period/shop, generate the document, and inspect summary, per-shop peso figures and appendix. Check print/HTML output.
18. Change bounded System Settings with a reason, then filter and inspect the corresponding Activity Log event.
19. Exercise Maintenance backup/restore, courier adapter, jobs, integrity and incident tools.
20. Run the browser suite, inspect responsive screenshots, rebuild twice and compare the generated HTML SHA-256.

See browser-regressions.json and VALIDATION.json for the current automated result. Server authorization, concurrency, real settlement, external delivery/email and legal invoice compliance require backend integration tests.
